QA Team Dashboard — Application & Data Flow Specification

Complete functional overview, role breakdown (Manager vs. Tester), and synchronized defect lifecycle.

1. System Architecture & Core Concept

The QA Team Dashboard centralizes testing project oversight, defect logging, and daily sprint tracking into a unified single-source-of-truth web application.

  • Authentication & Role Routing: Users authenticate at /login. Managers automatically land on /manager/overview; testers land on /tester/overview.
  • Decoupled Spreadsheets: External Google Sheets and Cloud Excel workbooks are stored purely as reference hyperlinks (excel_sheet_url). Testers open live sheets via one click without needing to enter manual counts.
  • Database Single Source of Truth: Every defect metric (Total, Open, Need Retest, Retested, Closed, Critical) is calculated directly from the bugs table.

2. Manager Persona Flow & Pages

Manager Executive View

1. Overview (/manager/overview)

Executive command center showing aggregate KPIs (19 Total Tracked: 9 Open, 2 Need Retest, 5 Retested, 3 Closed, 1 Critical), project defect distribution charts, and tester activity feeds.

2. Workspaces (/manager/projects)

Create new project workspaces, assign/unassign QA testers, attach/edit live Google Sheet links, and cascade-delete completed or retired projects.

Manager Operations View

3. Bugs & Focus (/manager/bugs)

Project Defect Overview table with "Live Sheet" launchers, and "Today's Active Focus & Retest Queue" highlighting today's tickets and blocker escalations.

4. Bug Audit (/bugs/list) & Team (/manager/team)

Company-wide searchable defect repository with category toggles (Bugs vs. Requirement Changes), multi-filters, and tester account provisioning.

3. Tester Persona Flow & Pages

Tester Daily Execution

1. Tester Overview (/tester/overview)

Personal workstation displaying assigned project scopes, personal defect breakdown, quick sheet launchers, and defect logging shortcuts.

2. Assigned Projects (/tester/projects)

Focused view of projects designated to this tester with "Live Sheet" links to external workbooks and "Edit Link" to update URLs.

Tester Quality Assurance

3. Defect Workbench (/tester/bugs)

Primary QA execution workbench. Testers select a project, log defects or requirement changes, advance status through retests, and auto-alert managers on Critical blockers.

4. Daily Progress (/tester/progress)

Submit daily sprint progress (% completion, sprint name, remarks). Updates manager dashboards and activity feeds in real time.

4. End-to-End Data Flow

Step 1 Project Setup & Assignment: Manager creates a project with dates and sheet reference link at /manager/projects, then assigns one or more testers.
Step 2 Test Run & Defect Discovery: Tester opens /tester/projects, clicks Live Sheet to inspect test cases, and logs defects via /tester/bugs.
Step 3 Automatic Alerts & Retest Cycle: If marked Critical, managers receive immediate notification. Once developers deploy a fix, the tester changes status: Open → Need Retest → Retested → Closed.
Step 4 Daily Progress & Synchronization: Tester logs daily progress at /tester/progress. The manager's dashboard and activity stream reflect the milestone.
Step 5 Audit & Reporting: Both roles use /bugs/list to filter, audit history, toggle between bugs and requirement changes, and generate reports.
